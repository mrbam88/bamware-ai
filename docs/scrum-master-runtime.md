# Persistent Scrum Master — bounded resident implementation (#79)

The Stakeholder / CEO owns outcomes, priorities and reserved decisions, not routine task chasing. Chief of Staff is the primary executive interface: COO responsibility for healthy operations plus personal-assistant/sounding-board support. One shared Scrum Master owns delivery evidence, follow-through and escalation across projects; engineering workers execute bounded implementation/testing assignments. Personal context stays in private storage and is not sent to worker prompts or public records. No additional communications/account permissions follow from these roles.

## What runs

The existing assistant-web.service on omarchy hosts this logical Scrum Master. It reuses the owner-blocker scheduler (one-minute sweeps), with public GitHub metadata reads at most every15 minutes per explicit assignment. There is no second daemon, timer, endless inference or new model call. Source requests use a five-second timeout, no redirects and no credentials. Body/comments/logs are not retained; only issue/PR identity, state, updated timestamp, draft/merged/head revision are observed. Closed/merged alone never marks engineering work complete. Deterministic assessments turn unavailable sources into recheck actions, changed PR heads into stale-review findings, open drafts into pending review/release prerequisites and unassigned voice implementation into handoff pending. They do not dispatch, merge or send routine task chasing back to the CEO.

Durable `.scrum-master.json` beside the existing blocker ledgers contains role definitions, the stable CoS→Scrum Master mandate, acceptance receipts and three actual assignments: auth85 release supervision, Discuss92 session-worker checkpoint and voice62 readiness. Imported handoff/QA claims are explicitly historical reported evidence, separate from fresh source observations. The session implementation worker is not a server-controlled live worker. No duplicate coding dispatch occurs.

Mandate ID, scope, revision and founder approval source are validated. Enabled/paused/revoked state survives restart; revoked authority cannot be silently re-enabled. Each real sweep persists pickup before work, then a completed/partial/failed **supervision** receipt; interrupted runs recover as failed, not completed engineering. The latest30 receipts are retained; acceptance receipts and last-success timestamp persist separately. No new public mutation endpoint is added.
